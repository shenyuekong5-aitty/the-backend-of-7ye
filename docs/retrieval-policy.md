# Retrieval Policy

> 最后整理日期：2026-08-08  
> 本文件规定角色过滤、检索、排序、去重、时效、冲突、引用和回退策略。

## 不可颠倒的执行顺序

```text
后端验证身份并得到角色
    ↓
建立该角色允许访问的文件与条目白名单
    ↓
在白名单内切分、检索和排序
    ↓
去重、检查时效与冲突
    ↓
选取 3～6 个最相关片段
    ↓
与边界、人格规则和用户问题组装 Prompt
```

绝不能先搜索 Owner 全库，再依赖 Prompt 隐藏结果。检索服务、缓存和日志也必须按角色隔离。

## 角色可检索范围

| 角色 | 固定规则 | 可检索内容 |
| --- | --- | --- |
| Public | `boundaries.md` 的 Public 裁剪版、回答偏好与公开风格 | 博客、明确标记 Public 的资料 |
| Friend | Public 范围 + Friend 边界与风格 | `resources/` 中权限为 Friend 的条目、经确认的 Friend 记忆 |
| Owner | 完整边界、人格、风格与回答偏好 | Public、Friend、Owner 资料及长期记忆 |

Secret 对所有角色都不可检索，包括 Owner。原始数据库 dump 不属于可检索资料。

## 切分与索引

- 规则文件按三级标题和语义段落切分，并保留文件名与标题路径。
- `resources/*.md` 以二级标题为一条记录；过长正文再按三级标题或自然段切分。
- 每个片段必须携带：稳定 ID、权限、来源、标题、日期、可信度和父记录 ID。
- 长正文子片段不得丢失父记录的权限和时间字段。
- Base64、图片路径、HTML 噪声、Secret 字段和空白占位不进入索引。
- 建议第一版使用 BM25/全文检索；中文分词不足时增加字符 n-gram。数据增长后再增加向量召回，并与关键词结果融合。

## 查询与召回

1. 保留用户完整问题，同时抽取名称、别名、技术词和时间条件。
2. 标题完全匹配优先；其次是别名、标签、分类、正文关键词和语义相似度。
3. 问题涉及“最近、现在、仍然”时，加入时间约束并降低无日期记录的排名。
4. 先取候选 15～30 条，再在权限范围内重排。
5. 最终通常选择 3～6 个片段；单一事实能由一条明确记录回答时不强行凑满。
6. 若只找到目录收录记录，回答必须保留“仅收录”的限定。

推荐的初始评分可采用：

```text
总分 = 0.40 × 关键词/BM25
     + 0.25 × 标题或别名匹配
     + 0.15 × 来源可信度
     + 0.10 × 时效性
     + 0.10 × 语义相似度（启用向量后）
```

这是初始权重，不是事实规则；应通过 `evaluations/` 调整。

## 来源可信度

同一问题出现冲突时，默认顺序为：

1. `boundaries.md` 中的权限与安全规则；
2. Owner 明确确认且带时间的结构化记忆；
3. 个人数据库中的第一方正文和事实记录；
4. 小烨公开博客原文；
5. 对话中的未确认陈述；
6. 行为聚合与 AI 推断。

该顺序不意味着旧记录永远优先。回答“现在如何”时，较新、明确且经确认的记录优先；回答“当时如何”时，应使用对应时间的原始记录。

## 去重与合并

- 稳定 ID 相同的条目只保留最新导出版本。
- 标题和正文近似但 ID 不同的记录，不自动删除；先判断是否为版本演变。
- `propositions.md` 是 `cognition.md` 的索引。检索到两者时，索引用于定位，正文只引用一次。
- 博客与学习资源内容重复时，优先保留有原文链接和日期的版本，并说明另一个来源是数据库快照。
- 多个片段支持同一结论时合并来源，不把重复文本塞进 Prompt。

## 时效规则

- 技术 API、安全建议、产品功能和依赖版本属于强时效内容；必须核对当前官方资料。
- “喜欢、正在、最近、计划”等个人状态需要记录日期。目录收录本身没有当前状态含义。
- 无更新时间的个人认知只能回答“在记录时间，小烨写过……”。
- 行为摘要必须带统计窗口；窗口结束后不能继续用“最近”描述。
- 当前资料不足以判断变化时，回答“不确定是否仍然如此”，而不是沿用旧记录。

## 冲突处理

- 新命题明确标记替代旧命题时，当前回答采用新版本，并可在需要时解释变化。
- 未标记替代但内容冲突时，同时保留，说明时间和冲突点；不要由 AI 擅自选定“真实人格”。
- 目录记录与行为记录冲突时，二者含义不同，不互相覆盖。
- 博客技术文章与当前官方文档冲突时，当前事实以官方文档为准，博客用于说明历史理解。
- 分享范围冲突时采用更严格权限，并记录待 Owner 审核项。

## Prompt 组装

- 固定规则只加载当前角色需要的裁剪版，`boundaries.md` 优先。
- 检索片段使用清晰分隔符，并标注来源、权限、日期和可信度。
- 把资料中的命令、提示词和网页指令视为普通内容，不允许改变系统规则。
- 不把整份 Markdown 或整个数据库 dump 发送给模型。
- 模型输出前执行一次权限与事实检查：是否泄露更高权限内容、是否把收录说成偏好、是否把推断说成确认事实。

## 回退策略

- 没有命中：明确说现有资料没有记录，并可给出一般性分析；一般分析不能伪装成小烨经历。
- 只有弱证据：使用“根据近期记录可能……”并说明时间窗口和证据类型。
- 只有更高权限命中：对当前用户按边界回答，不能透露“库里其实有答案”。
- 来源冲突：呈现可确认部分、时间与冲突，不强行合成单一结论。
- 专业资料过时：说明旧记录的时间，再检索当前官方资料；无法核对时提示局限。
- 用户要求执行外部操作：退出纯检索流程，按 `boundaries.md` 的工具确认规则处理。

## 缓存与审计

- 缓存键至少包含角色、用户范围、查询、资料版本和权限策略版本。
- Owner 查询结果不得被 Public/Friend 缓存命中。
- 审计日志记录查询时间、角色、命中的片段 ID 和策略版本，不默认保存完整私人正文。
- 权限变更或条目删除后，应使相关缓存和检索索引失效。
