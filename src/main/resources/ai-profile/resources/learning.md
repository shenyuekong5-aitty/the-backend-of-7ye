### 内容

MVVM 是 Model-View-ViewModel 的缩写。Model 负责数据与业务逻辑，View 负责界面展示，ViewModel 作为桥梁连接二者。ViewModel 通过 DOM Listeners 监听 View 变化并更新 Model，通过 Data Bindings 监听 Model 变化并更新 View，实现数据驱动的双向绑定。

### 优点

清晰分离视图与数据，降低耦合；ViewModel 可独立测试；数据驱动视图，减少手动 DOM 操作。

### 局限

对于简单页面可能过度设计；需要理解响应式原理，初学者有一定上手成本。

### 内容

ref 用于将基本类型数据（如 string、number）包装为响应式对象。真实数据存储在 .value 属性中，模板中自动解包，脚本中需通过 .value 访问。ref 会自动推断 TypeScript 类型，修改 .value 会触发视图更新。

### 优点

使基本类型获得响应式能力；模板自动解包，使用便捷；TypeScript 类型推断良好；可传递单个响应式值。

### 局限

脚本中必须使用 .value 访问，稍显繁琐；对于对象，内部仍会调用 reactive 处理。

### 内容

shallowRef 创建仅对 .value 第一层变化敏感的 ref，深层属性修改不会触发更新。shallowReactive 仅对对象顶层属性做响应式代理。适用于大型数据或与外部系统集成时避免性能开销。

### 优点

减少深层响应式追踪，性能更优；适合第三方库对象或大型列表；可手动调用 triggerRef 强制更新。

### 局限

深层数据修改无法自动响应，易造成误解；需明确使用场景，否则可能引发 bug。

### 内容

v-for 用于基于数组渲染列表。设置唯一 key 后，Vue 的虚拟 DOM diff 算法会复用未变化的 DOM 元素，提高渲染性能。不设置 key 时，Vue 会尽量复用，可能导致状态错乱。

### 优点

key 优化 diff 性能，精准更新 DOM；避免输入框等状态错位；便于追踪元素身份。

### 局限

不设置 key 可能引发渲染异常；key 需保证唯一且稳定（避免用索引）。

### 内容

WebSocket 是一个全双工通信协议，允许服务端主动向客户端推送消息，打破了 HTTP “一问一答”的限制。它既涉及后端，也涉及前端。
在 HTTP 握手之后，将连接升级为持久化连接
客户端和服务端可以随时互相发送数据，无需反复建立连接。

### 优点

非常适用于聊天、实时通知、协作编辑等需要低延迟双向通信的场景

可以同时支持多个客户端的实时交互，适合多人协作场景
开发效率高，借助成熟的框架可以快速实现功能
易于扩展，可以在此基础上实现实时白板、在线游戏等复杂功能

### 局限

开发和维护成本比传统 HTTP 接口高
对服务器的稳定性要求高，连接断开会影响用户体验
消息的持久化和历史记录查询需要额外实现
大规模并发时需要使用消息队列进行削峰填谷
安全要求高，需要对消息进行加密和权限校验

困扰人们的往往并非事物本身，而是人们对事物的看法。斯多葛派哲学家爱比克泰德的这句名言，直指情绪困扰的根源。堵车本身没有烦躁的属性，考试落榜也不等于人生完蛋——正是我们内心对事件的判断，赋予了外界伤害我们的能力。

### 内容

axios是一个基于Promise的客户端库，支持浏览器和node.js，封装好了原生的XMLHttpRequest和node.js的http模块，让我们无需关注底层的请求构建、状态监听、错误回调等操作，极大的节约了我们的开发成本

axios主要是通过create构建一个实例，该实例能够配置baseURL、timeout、全局请求头（如content-type）等。比如当后端服务器地址发生改变时，仅需要修改baseURL，而无需修改可能的成百上千个文件

axios还可以设置请求拦截器和响应拦截器，请求拦截器可以统一携带请求的附加信息，比如用户的token，响应拦截器则可以处理响应过来的各种信息，如判断错误类型等，剥离后端的响应包装层，保证只返回业务数据

axios还可以封装通用请求，如get、post、put、delete等

### 优点

1.自动转化为JSON格式
2.支持请求取消
3.设有拦截器
4.支持超时配置

### 局限

无

### 内容

感知轴

判断轴

上面八个维度就是荣格提出的心理类型， 但荣格本人没有提出 "感知轴 / 判断轴" 的概念，也没有完整的 "八维功能排列" 理论。这些是后来 MBTI 创立者迈尔斯母女，以及荣格派心理学家约翰・毕比等人在 20 世纪中后期逐步完善的。

第一个为i，第二个必须为e，第三个为i，第四个为e，反之亦然
